# data_models — persistence schema

[← Back to BACKEND.md](../BACKEND.md) · [API reference](data_models_API_DOCS.md)

SQLAlchemy models for the server path, plus the session factory.

## The problem

The TUI is single-user and SQLite is enough. The server is not: several people
share one process, and a chunk leaking across users is a data breach, not a bug.
The schema has to make isolation structural rather than a thing every query
remembers to do.

## Design

### Tenant isolation by construction

Every user-owned table carries `user_id` with `ON DELETE CASCADE`:

```
  users
    ├── documents ──▶ chunks ──▶ embeddings
    ├── cache_topics
    └── history_sessions ──▶ history_turns
```

Cascade means deleting a user removes their documents, chunks, embeddings,
cache and history in one statement, at the database level — no application code
to forget.

`user_id` is indexed on every such table because it appears in the `WHERE`
clause of essentially every query.

### Keys

UUID primary keys with `server_default=func.uuid_generate_v4()`, so IDs are
generated by PostgreSQL rather than the application. This requires the
`uuid-ossp` extension:

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

`chunks.id` is the exception — a `Text` primary key holding the content-addressed
chunk hash from the ingestion pipeline. Reusing that hash rather than minting a
surrogate is what keeps re-ingestion idempotent across the FAISS index and the
database at once.

### Sessions

`SessionLocal` is a plain `sessionmaker` with `autocommit=False` and
`autoflush=False` — explicit transaction boundaries. `get_db()` is the FastAPI
dependency: yield a session, close it in `finally`.

> `get_db` deliberately does **not** catch exceptions. FastAPI throws a route's
> exception back into the generator at the `yield`; wrapping it converted every
> `HTTPException` into a bare `Exception`, and the framework's handler turned
> that into a 500 with the status code and detail lost. Wrong credentials
> returned "Internal Server Error" instead of 401. `try/finally` only.

## Trade-offs and gaps

- **No migrations.** No Alembic; the schema is whatever `Base.metadata` last
  created. Adding a column means doing it by hand.
- **`embeddings.faiss_id` is written but never read.** Retrieval maps FAISS
  positions back to chunk IDs through `HNSWIndex.id_map` instead, so the column
  is bookkeeping that can drift from reality.
- **`cache_topics` cannot store what the cache needs.** There is no chunk-IDs
  column, which is why the server's cache adapter is a stub.
- **`history_turns.query_text` stores `"role: content"` as one string**, parsed
  back by prefix. A `role` column would be the honest shape.
